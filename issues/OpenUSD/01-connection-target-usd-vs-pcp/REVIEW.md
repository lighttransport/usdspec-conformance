Item: OpenUSD/01-connection-target-usd-vs-pcp
Verdict: DO NOT FILE as a bug (not a bug: the Usd/Pcp difference is documented, deliberate API behaviour). At most, file a short question or docs request (see Required edits).
Reviewer environment: official PyPI wheels usd-core==26.11 and usd-core==26.5 (stock builds, Python 3.11, Linux x86_64); OpenUSD source tag v26.11.1 and origin/dev 2d39590aa (2026-10-29), read via git
Claims checked:
  - [OK] `python repro.py` with stock usd-core 26.11 prints exactly the four lines in the draft (plus two "outside the scope of the inherit" warnings on stderr). usd-core 26.5 gives the same four lines.
  - [OK] Error types and messages match: for L, ErrorInvalidExternalTargetPath "</Rig/Anim/L.value> ... refers to a path outside the scope of the inherit from </Rig/L>. Ignoring." and ErrorInvalidInstanceTargetPath "</Rig/Anim/R.value> ... is authored in a class but refers to an instance of that class. Ignoring."; R symmetric. Same results whether the Pcp.Cache is created with usd=True or not (repro.py uses the default, usd=False; Usd itself uses a USD-mode cache, so use usd=True).
  - [OK] Flatten (UsdStage.Flatten() from usd-core 26.11; usdcat binary not in the wheel) writes `amount.connect = </Face/Anim/R.value>` for L and `</Face/Anim/L.value>` for R.
  - [NOT A BUG] Cause found in v26.11.1 source: UsdProperty target composition calls PcpComposeTargetPaths (pxr/usd/usd/property.cpp L199), which does no validation that needs a cache. The class-targets-instance check in pxr/usd/pcp/targetIndex.cpp L368-386 runs only `if (cacheForValidation)`; PcpBuildTargetIndex passes 0 (L775), and its header says "this function will skip the validation checks performed by PcpBuildFilteredTargetIndex". PcpCache::ComputeAttributeConnectionPaths uses PcpBuildFilteredTargetIndex with the cache, so it validates. The "outside scope" check is done in both because it is part of path translation. So the difference is by design (validation that needs extra prim indexes is skipped on the Usd hot path). OpenUSD also has testPcpMuseum_ErrorInvalidInstanceTargetPath run in --usd mode (pxr/usd/pcp/CMakeLists.txt L1340), so the Pcp-side errors are tested expectations.
  - [OK] dev: no changes to usd/property.cpp, pcp/targetIndex.cpp or usd/stage.cpp between v26.11.1 and origin/dev (git diff empty), so dev behaves the same (not built).
  - [OK, but not this issue] Release change on the corpus scene: with the official wheels, 26.5 GetConnections/Flatten give both targets, 26.11 gives only the RBrow target; 26.5 Pcp gives [/FaceRig/BrowRig/Anim/LBrow.InnUD] + 1 error (= corpus pcp.txt), 26.11 Pcp gives [] + 2 errors. Probably the v26.11 relocation fixes (f0a7d06e7 "Fixes to how Pcp handles invalid opinions at relocation source paths"); intended, not bisected.
  - [OK] Licensing: ref.usda/root.usda/repro.py are original reductions (renamed prims, different structure: single reference, no second relocate) and not copied from the corpus or spec.
