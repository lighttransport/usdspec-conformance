Claims checked:
  - [OK] Quoted sentence is in "Anti-Regression at Evaluation Time" (core_spec.md L8086-8095). Strategy table row "Keep Ratio ... until the non-regressive limit is reached" is L8066. Backward-facing tangents treated as zero-length: L8054-8056 (draft's "backward-facing tangent rule" is correct).
  - [OK] Derivation: with control times 0, a, 1-b, 1, x'(u)/3 = a(1-u)^2 + 2(1-a-b)u(1-u) + b u^2 with a,b >= 0; non-negative on [0,1] iff (1-a-b) >= 0 or (1-a-b)^2 <= ab. On the boundary with a,b scaled by s: s(a+b) - 1 = s*sqrt(ab), so s = 1/(a+b-sqrt(ab)); a=b=1.2 gives 0.8333. Matches OpenUSD's own closed form: `_AdjustWithKeepRatio` computes opposite = (sqrt(r)+r+1)/(r^2+r+1), active = r*opposite, which is the same expression rationalised.
  - [OK] pxr value: `double v.spline = { bezier, 0: 0; post curve (12, 10), 10: 10; pre (12, 10), }` evaluated at t=4 with usd-core 26.11 -> 29.97398957136784 (exact match).
  - [OK] Independent exact-limit value (bisection on the Bezier time curve, widths 10, slope 10): 29.974239465873676 (draft 29.974239465872969; same to 1e-13). With widths 10*(1-1e-5): 29.9739895876, i.e. pxr = exact limit minus 1e-5 normalised padding. Relative gap 8.3e-6 ("about 1e-5" is acceptable).
  - [OK] v26.11.1 regressionPreventer.cpp L171 `kWritePadding = 1e-5`, L176 `kReadPadding = 1e-6`; `_AdjustWithKeepRatio` (L714-737) subtracts kWritePadding from both widths, so the ratio is not exactly preserved for unequal widths. Draft quotes these correctly.
  - [MISSED by draft] Spec "Value Resolution Compliance" (core_spec.md L643-652) already says: interpolated values between exact values (authored samples, spline knots) "may deviate a small amount from an evaluation of the reference interpolator", and a Note says "A specific numerical tolerance is not prescribed". So the second option in the request ("state that results within some tolerance are conformant") is largely already in the spec.
